## Bring-up efter reboot (boks 1)

```bash
# find boksen (IP skifter): bash devuan/find_box.sh
ssh -i ~/.ssh/geekbox_key root@<ip>
insmod /root/pvrsrvkm_leddaz.ko
sh /root/gpu_up.sh                       # forvent pvrsrvctl-exit=0 (eller 1 = allerede init)
sed "s/BOX=root@192.168.0.188/BOX=root@<ip>/" \
  devuan/gpu/eglplatform_x11/patch_android_bindapi.sh > /tmp/pb.sh && bash /tmp/pb.sh
# verificér:
timeout 30 env LD_PRELOAD=/root/system_shim.so LD_LIBRARY_PATH=/opt/hybris \
  EGL_PLATFORM=x11 DISPLAY=:0 /root/gl_version_probe   # GL_VERSION 1.5@3830101
timeout 40 env LD_PRELOAD=/root/system_shim.so LD_LIBRARY_PATH=/opt/hybris \
  EGL_PLATFORM=x11 DISPLAY=:0 /root/shader_ext_test    # ES2+ES3 draw_buffers OK
```

nåede (den prøver igen i baggrunden).

## Næste skridt (BESLUTTET 26. aug: gralloc-lock-sporet)

**Brugeren har valgt at forfølge gralloc-lock-sporet** (ikke Spor B, ikke accept).
Mål: få præsentationen til skærmen til at virke i Firefox' GPU-proces, så Subway
Surfers kan rendere.

**Spor-status (hvad der er afkræftet):**
- IKKE shaders (0 compile-fejl, 0 kontekst-tab med proxy-omskrivningen).
- IKKE syscall 403 (compat-fixet kører; 0 "syscall 403"-spam).
- IKKE GRALLOC_USAGE-værdier (x11ws patchet med korrekte AOSP-konstanter; fejler
  stadig).
- IKKE 1.4-gralloc (SIGILL mod 1.5).
- IKKE handle-format (v=12 f=3 i=35, identisk med standalone).
- **FEJLBILLEDE:** gralloc-lock EINVAL på ALLE buffere i Firefox' GPU-proces
  (selvt est i x11ws: alloc OK, lock=-22 på frisk buffer med samme module);
  standalone (selv efter eglInitialize) = OK. → processpecifik PVR-klient/
  driver-tilstand.

**Næste undersøgelses-skridt (rækkefølge):**
1. Find EINVAL-kilden i 1.5-gralloc'ens `lock` (disassemble; modulet er strippet,
   find lock via module-structs funktionspointer — offset i .data; find den
   `mov r0,#-22`/`mvn r0,#21`-retur + hvad der udløser den).
2. Afgør hvilken `libsrv_um.so` GPU-processen vs. standalone faktisk bruger
   (maps: /system/vendor/lib/libsrv_um.so vs. andet) + om PVR-klient-
   forbindelsen (/dev/pvrsrvkm-ioctls) afviger.
3. Hook/straccé lock-kaldet i GPU-processen (udvid egl_proxy/x11ws til at logge
   ioctl-return fra lock-stien) — find det kald der returnerer EINVAL.
4. Sammenlign PVR-klient-state: hvilke services er oppe (logd/servicemanager/
   pvrsrvctl) når GPU-processen starter vs. standalone-testen.

Uanset spor:
- Næste kernel-byg: `CONFIG_ANDROID_PARANOID_NETWORK` FRA + bcmdhd (wifi).
- NTP-undersøgelse (chrony).
- Overvej at automatisere GPU-bring-up i myinit (insmod + gpu_up + bindapi).
